# Talentro — мобильное приложение (Flutter)

Зона ответственности: `frontend/mobile/**`. Статус работы ведётся здесь и в
сообщениях координатору; в `web/COORDINATION.md` не пишем.

Ветка: `feat/mobile-flutter-mvp` (работает в git worktree `.worktrees/mobile`,
чтобы не трогать общее дерево `main` с чужими незакоммиченными правками).
Формат ветки — `docs/git-rules.md`; номер задачи в трекере найти не удалось
(GitLab/GitHub- Issues недоступны сессии), поэтому имя согласовано с координатором.

## 1. Стек

| Слой | Выбор | Версия | Почему |
|---|---|---|---|
| SDK | Flutter stable / Dart | 3.47.8 / 3.13.7 | установлен в системе, проверен `flutter doctor` |
| State management | Riverpod | `flutter_riverpod: ^3.4.3` | `Notifier`/`AsyncNotifier` дают отдельное состояние запроса (loading/error/data) без ручных флагов; провайдеры переопределяются в тестах |
| HTTP | Dio + `dio_cookie_manager` | `dio: ^5.11.1`, `dio_cookie_manager: ^3.5.0`, `cookie_jar: ^4.0.9` | сервер ставит сессию в HttpOnly-куку `talentro_session`, поэтому нужен `CookieJar`, а не хранилище токена. | Роутинг | go_router | `go_router: ^18.1.2` | deep-link на карточку `/activity/{slug}` работает из списка и из будущего пуша |
| UI | Material 3, без UI-кита | — | дизайн-система перенесена из `web/src/app/globals.css` в `ThemeData` (см. §4) |

iOS не собирается нигде: ТЗ §14 прямо запрещает artefact для iOS, цель MVP —

## 2. Структура

```
lib/
  main.dart                     ProviderScope + MaterialApp.router
  app/
    router.dart                 / (каталог), /activity/:slug
    providers.dart              apiConfigProvider, apiClientProvider (с dispose)
  core/
    api_config.dart             базовый URL из --dart-define, маршруты v1
    l10n.dart                   все подписи интерфейса одним файлом
    theme.dart                  токены из globals.css -> ThemeData
  data/
    api/api_client.dart         Dio: таймауты, CookieJar, разбор конверта §9.3
    api/api_failure.dart        ApiFailure {statusCode, code, message, fields, transport}
    models/                     json.dart (приведение типов), activity*.dart,
                                activity_parts.dart (группы/точки/орг), media.dart,
                                reference.dart (справочники)
  domain/
    catalog_query.dart          сборка query-string, без клиентской фильтрации
    price.dart                  правило цены (Бесплатно / от N / не указана)
    format.dart                 склонения, возраст, расписание, адрес, даты
  features/
    catalog/                    контроллер + экран + плитка + состояния
    activity/                   карточка занятия (детали по §3.3)
test/
  fixtures/api/                 снимки живых ответов :8081 от 4 ноября 2026
  data/, domain/, core/         68 unit-проверок
  features/                     9 widget-проверок (состояния каталога и карточки)
```

Правила, которые держим явно:

* **Фильтрует сервер.** Клиент только собирает query (§6.3 прямой запрет на свою
  логику фильтрации). Пустые значения в query не пишутся (§5.9), район без города
  и радиус без точки не отправляются вовсе — сервер отвечает 400 (§5.4, §5.8).
* **Против моков не кодируем.** Фикстуры в `test/fixtures/api/` — снимки реальных
  ответов, модели собраны по контракту Агента 2 (`backend/Talentro/API.md`) и
  проверены по этим снимкам: `photos[]`/`videos[]` — типизированный
  `{path, caption, source_url, author, order_num}`, а не сырой JSON.
* **Справочники — только с API** (`/categories`, `/cities`, `/districts?city=`);
  из `web/src/lib/data.ts` ничего не копируется.
* **Сессия — в `CookieJar`.** Сейчас in-memory: переживает навигацию внутри запуска,
  но не перезапуск приложения. Персистентность — открытый вопрос (см. §7).
* **Состояния `AsyncValue` разбираем по `hasValue`/`hasError`, а не по типу.** В
  Riverpod 3.4.3 упавший `AsyncNotifier.build()` оставляет `AsyncLoading` с
  `hasError == true`, а не `AsyncError` (проверено контейнерным тестом на трёх видах
  ошибки). Разбор `switch (state) { AsyncError … }` спрятал бы недоступный сервер за
  вечно крутящимся скелетоном — прямой нарушение §3.1.8.

## 4. Токены и доступность

Источник — `:root` из `web/src/app/globals.css` (читался read-only), значения
перенесены в `ThemeData`, классы не копируются (§10.16: приложение и сайт выглядят
как один продукт).

* цвета: `--accent #6D48DB`, `--bg #F6F2FF`, `--ink #201B3D`, `--line #EAE4F8` и т.д.;
* шкала карточек после подъёма кегля: тег 9 px, подпись действия 11 px, цена 13 px,
  заголовок 14/16 px (§15.6);
* **тап-зоны 44 px** (§10.6): `minimumSize: Size(0, 44)` у всех трёх кнопочных тем;
* **шрифт в полях ввода 16 px** (§3.5 п.5 — меньше нельзя, фокус зумит экран);
* красный для цены не используется нигде (§10.3) — закреплено тестом.

Проверки §10.6/§15.6 закреплены не глазами, а `test/core/theme_test.dart`.

## 5. Как запустить и проверить

```bash
cd frontend/mobile
flutter pub get
flutter analyze          # сейчас: No issues found
flutter test             # сейчас: 77/77 passed (68 unit + 9 widget)

# адрес API задаётся сборкой, в коде его нет

```

`10.0.2.2` — это хост-машина из Android-эмулятора; дефолт в `ApiConfig` именно он.
Порты `:3000`, `:3010`, `:8080`, `:55432` не занимаем; сервер на `:8081` только
читаем.

## 6. Что блокирует сборку APK

`flutter build apk` сейчас невозможен. Факты `flutter doctor` от 4 ноября 2026:

```
[!] Android toolchain - develop for Android devices (Android SDK version 36.0.0)
    X cmdline-tools component is missing.
    X Android license status unknown.
      Run `flutter doctor --android-licenses` to accept the SDK licenses.
```

То есть SDK сам по себе есть (36.0.0), но нет `cmdline-tools` и не приняты
лицензии. Минимальный путь к APK — два шага, оба ставят системные компоненты,
поэтому **без явного разрешения владельца ничего не устанавливаем**:

1. скачать/распаковать `commandlinetools` в `$ANDROID_HOME/cmdline-tools/latest`
   (архив с developer.android.com, либо установка Android Studio);
2. `sdkmanager --licenses` (или `flutter doctor --android-licenses`) — принять
   лицензии, после чего `flutter build apk --debug` становится возможным.

До этого момента качество проверяется `flutter analyze` + `flutter test`;
поведение на устройстве (скролл, `RefreshIndicator`, клавиатура, реальные 44 px)
пока не подтверждено — это честно отмечается в чекпоинтах.

## 7. Открытые вопросы координатору

### Что закрыл контракт `API.md`

Сверка 4 ноября 2026 сняла шесть вопросов из прежнего списка:

* **Тип идентификатора** — `id` карточки строка (`"10"`), `org_id` / `location_id` /
  `group_id` / `category_id` и id справочников — числа. Так и разобрано в моделях.
* **Нумерация `weekday`** — `1` … `7`, где 1 — понедельник; та же нумерация у
  параметра `day`. Разбор в одном месте (`domain/format.dart`).
* **Форма медиа** — `{path, caption, source_url, author, order_num}`, пустой список
  это `[]`, а не `null`. Типизировано в `data/models/media.dart`, сырого JSON не осталось.
* **Наднаправление** — отдельного параметра нет: родительский slug в `category` тянет
  все дочерние (§5.5). На выдаче оно приходит полями `super_category` /
  `super_category_slug`.
* **Районы** — параметр `district` принимает список через запятую и только вместе с
  `city`; без города сервер отвечает 400 с `fields.city` (снимок —
  `districts_no_city_400.json`).
* **Занятия организации** — фильтра `?org=` нет и не будет; есть
  `GET /api/v1/organizations/{slug}` → `OrganizationPage`.

### Открытые вопросы координатору

1. **Вход и роли.** В контракте раздел «Чего в контракте ещё нет»: `/api/auth/*` и
   `GET /me` не реализованы, и просят не включать мок-авторизацию. Модель сессии и
   маршруты из клиента убраны (возвращались вместе с маршрутами сервера), `CookieJar`
   в транспорте оставлен — он дешёвый и нужен будет в тот же день. Когда ждём срез
   авторизации? От него зависят §3.7, избранное и «заявка».
2. **`sort`.** Сервер принимает `updated | price | name | verified` (по умолчанию —
   новые сверху), а §3.1.6 просит ещё релевантность, «рядом со мной», рейтинг и
   «бесплатные». `rating` контракт прямо объясняет 400. Клиент белый список не
   расширяет: нужен либо срез сервера, либо подтверждение, что в MVP этих сортировок нет.
3. **«Утро/день/вечер» против `time=ЧЧ:ММ`.** §3.1.3 просит промежуток, сервер принимает
   момент внутри `time_from…time_to`. Если чип «Вечер» превращать в `time=18:00`,
   занятие в 17:00–19:00 попадёт, а в 20:00–21:00 — нет. Просим либо три момента от
   вас, либо серверный диапазон `time_from`/`time_to`; сами промежутки не выдумываем.
4. **Период цены у услуги.** §3.4 просит «цена за час или визит», а CHECK в схеме
   допускает только `session | month | course`. Сейчас `session` подписываем словом
   ТЗ «за тренировку» — для репетитора это звучит странно. Какую формулировку берём?
5. **Дата проверки в списке.** `items[]` несёт только флаг `verified` (он же
   `contacts_verified_at` карточки не старше 90 дней), даты в плоской строке нет —
   поэтому в плитке флаг, а не «проверено ДД.ММ». Просим дату в списке или
   подтверждаем текущий вид.
6. **Медиа-хост.** `photo` и `photos[].path` — относительные пути, базовый адрес не
   согласован. Пока обложка — штатное «Фото нет», сетку не тянем.
7. **Кэш и офлайн.** Сервер отдаёт `Cache-Control: public, max-age=60` и слабый
   `ETag` со `304` на список и карточку. Dio их не переиспользует сам; нужен ли в MVP
   условный запрос (поведение §3.1.8 при перезапуске без сети) — или это следующий этап?
8. **Постоянство сессии.** In-memory `CookieJar` не переживает перезапуск. Нужна ли
   `PersistCookieJar` + `path_provider` в MVP — или выход на вход при каждом старте
   приемлем?
9. **Зависимости карты.** §3.5 требует OSM и кластеры; кандидат `flutter_map` +
   `flutter_map_marker_cluster`. Добавлять в этом чекпоинте или отдельным?
10. **Мессенджеры.** Таблица в схеме есть, в выдачу ещё не поднята — наружу идут
    только `phone`, `email`, `site`. §3.3 обещает кликабельные мессенджеры; Агент 2
    спрашивал, нужны ли они до заморозки 22.11 — ответ за владельцем, клиент готов
    принять их одним полем модели.
