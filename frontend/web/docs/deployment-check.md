# Как проверить, что опубликован актуальный фронтенд

Vercel должен собирать `web/`. Папка `frontend/web/` — устаревшая копия;
её не нужно синхронизировать и использовать для публикации.

1. Объединить исправления фронтенда в `main`.
2. В проекте Vercel проверить Root Directory: `web` и выбранный коммит.
3. Опубликовать этот коммит как Production и дождаться успешной сборки.
4. Открыть `/api/build-info` на публичном домене.

Ожидаются `application: "talentro-web"`, `root_directory: "web"`,
`ui_contract: "2026-11-17.review-media-google-v2"` и признак
`persistent-review-media` в `features`. `revision` содержит SHA коммита,
если Vercel передал `VERCEL_GIT_COMMIT_SHA`; при сборке без этой переменной — null.
Здесь нет секретов или адреса базы. Ответ не кэшируется.

Если `/api/build-info` возвращает 404 или HTML, актуальная сборка по этому
домену ещё не подтверждена: нужно проверить Deployment и его Production alias.
Обычное обновление страницы не меняет серверную сборку.

После публикации проверить:

- Новый Google-пользователь: сначала один отдельный экран выбора роли,
  затем вход. Форма с почтой и паролем на этом шаге не отображается.
- Существующий Google-пользователь: вход без повторного выбора роли.
- Если создание принято, но проверка сессии не удалась: «Проверить вход»
  повторяет только GET `/api/auth/me`, без нового запроса регистрации.
- Отзыв с небольшим JPG: POST создания отзыва, POST его фотографии,
  затем GET отзывов должен содержать ID и путь к фотографии. После обновления
  страницы картинка остаётся. Локальный `blob:` допустим только для превью файла.
- Фото больше 4 МиБ и видео загружаются непосредственно в публичный Go API;
  его CORS должен разрешать текущий домен сайта.

Фотографии, показанные старой формой только через `blob:` и не загруженные
в API, не появятся в базе от обновления сайта: их нужно прикрепить заново.
