## API Endpoints

1. Получение списка организаций
   - Метод: GET
   - URL: /api/organizations
   - Параметры:
     - city: 'Тирасполь' | 'Бендеры' | … (см. `CityName`)
     - category: 'sport' | 'art' | 'language' | 'other'
     - age: number (один возраст ребёнка, §5.2 — не диапазон `ageGroup`)
     - priceType: 'free' | 'paid'
     - searchQuery: string
   - Ответ:
     ```typescript
     interface Organization {
       id: string;
       name: string;
       description: string;
       address: string;
       city: CityName;
       contacts: string;
       ageRange: [number, number];
       tags: string[];
       coordinates: Coordinates;
       reviews?: Review[];
       priceType: 'free' | 'paid';
       category: 'sport' | 'art' | 'language' | 'other';
     }
     ```

2. Получение данных организации
   - Метод: GET
   - URL: /api/organizations/:id
   - Ответ:
     ```typescript
     interface OrganizationDetails extends Organization {
       reviews: Review[];
     }
     ```

3. Получение списка категорий
   - Метод: GET
   - URL: /api/categories
   - Ответ:
     ```typescript
     interface Category {
       id: string;
       name: string;
     }
     ```

## Типы данных

Все типы данных определены в `src/types/index.ts`:
- `Coordinates` - координаты организации (`{ lat, lng }`, не tuple)
- `OrganizationCategory`, `PriceType`, `CityName` - машинные значения фильтров
- `Review` - отзыв об организации
- `Organization` - основная информация об организации
- `Filters` - параметры фильтрации (все поля необязательные)

## Тестовые данные

- `cityCoordinates` - центры городов, к которым летит карта при выборе города

### Найдено и исправлено

1. **`Filters.tsx` — фильтрация не работала в принципе.** Значения опций были
   человекочитаемыми (`'Спорт'`, `'Бесплатно'`), а в данных — машинные (`'sport'`,
   `'free'`): сравнение никогда не давало true. Теперь `value` берётся из
   `categoryOptions` / `priceOptions` (`src/lib/filter.ts`), подпись остаётся русской (§4.5).
2. **`Filters.tsx` — смена одного селекта обнуляла остальные.** `onChange` отдавал
   `{ category: name === 'category' ? value : '', ... }`, то есть любое изменение стирало
   два других поля. Компонент стал контролируемым: принимает `filters` + `onChange(patch)`,
   слияние делает `mergeFilters`, состояние живёт на странице.
3. **Фильтра по городам не было вовсе** (ни Тирасполя, ни Бендер). Добавлен селект из
   `cities`, а у `Organization` появилось обязательное поле `city: CityName` — раньше город
   приходилось угадывать из префикса `address` (§5.9).
4. **Возраст был возрастной группой** (`'3-6' | '7-12' | '13-18'`) вместо одного числа
   (§5.2). В `Filters` теперь `age?: number` + числовое поле с подсказкой при ошибке.
5. **Клик по маркеру ничего не делал.** В `Map.tsx` не было ни `Popup`, ни обработчиков.
   Добавлены: попоп (название, адрес, возраст, ссылка `/organization/:id`), `onSelect(id)`
   через `eventHandlers.click`, подсветка выбранного маркера, список результатов справа
   синхронизирован с картой в обе стороны.
6. **Маркеры были невидимы.** `Marker` без `icon` тянет `L.Icon.Default` с битыми путями к
   png под сборщиком. Теперь `L.divIcon` + стили `.mapPin` / `.mapPin--selected` в
   `src/styles/globals.css`.
7. **`Map.tsx` принимал не те данные.** Пропс был `markers?: [{ position: [lat, lng] }]` при
   `coordinates: { lat, lng }` в типе, и `/map` рендерил `<Map />` без пропсов — маркеров не
   было никогда. Теперь `organizations: Organization[]` (+ `activeCity`, `selectedId`, `onSelect`).
8. **`OrganizationCard.tsx` падал при рендере.** `<MapPin/>`, `<Phone/>`, `<Users/>`
   использовались без импорта (TS2304 → ReferenceError в браузере). Иконки импортированы из
   `lucide-react`; локальный дубль `interface Organization` с `coordinates: [number, number]`
   удалён — карточка использует общий тип из `@/types` (иначе мок в неё не передаётся).
9. **Звёздный рейтинг противоречил §10.2** («звёзд нигде нет»): удалён `rating` из `Review`
   и `Organization`, а также из мока. Потребителей в UI не было — проверка по grep.
10. **Глобальный CSS вне `_app`.** `import 'leaflet/dist/leaflet.css'` был внутри `Map.tsx`;
    в pages-router это ошибка сборки. Импорт перенесён в `src/pages/_app.tsx`.
11. **`/organization/[id]` был заглушкой** и показывал только `id`, хотя попап карты ведёт на

## Интеграция с бэкендом: фактический контракт (4 ноября 2026, QodeX)

### Что реально есть на сервере

`backend/Talentro/internal/delivery/http/route.go` регистрирует ровно два маршрута:

| Метод | Путь | Параметры | Ответ |
|---|---|---|---|
| GET | `/health` | — | `{"status":"ok\|error","database":"connected\|disconnected"}`, 503 если БД не отвечает |
| GET | `/api/cards` | `city_name`, `city`, `direction`, `age`, `price_max`, `q` | массив `models.Card` |

Форма элемента (`internal/models/cards.go`): `id` сериализуется **строкой**
(`json:"id,string"`), дальше `name`, `org_id`, `city`, `age: {min, max}`, `link`,
`description`, `district`, `price`, `category`. `rows.Scan` в `repository.SearchCards`
заполняет только `id`, `name`, `city`, `age.min`, `age.max` — остальные поля всегда
`null`/`0`. Условий `direction`, `price_max` и `q` в SQL нет (закомментированы в
`repo.go`), сервер фактически фильтрует только по городу и возрасту. Ошибок в формате
§9.3 сервер не отдаёт — `http.Error` текстом.

Отдельно: `config.Load()` читает `ALLOWED_ORIGINS`, но CORS-промежуток в chi-роутере не
подключён, поэтому запрос из браузера (`:3000` → `:8080`) упрётся в CORS. Обращаться к
бэкенду нужно с сервера — так и сделано: компоненты App Router. И `database/init.sql`
создаёт только таблицу `users`; таблиц `cards` и `cities` в инициализации нет, то есть
`go run ./cmd/app` с этим скриптом упадёт на первом же запросе.

### Что сделано на фронтенде

1. **`src/lib/api.ts`** — транспорт под фактический контракт: типы `ApiCard`/`ApiHealth`/
   `CardQuery`, `ApiError { status }`, `apiBaseUrl()` из `NEXT_PUBLIC_API_URL`, `fetchCards()`,
   `fetchHealth()`. Из предыдущей версии убраны клиенты к `/organizations`, `/activities`,

## Живой стенд Postgres + Go + Next (4 ноября 2026, вечер)

### Причина блокировки и что исправлено в схеме

`database/init.sql` создавал только таблицу `users`, а `repository.SearchCards` читает
`cards JOIN cities` — то есть фронтенд было нечем проверить в принципе. Скрипт переписан:

- `cities (id, name)` и `cards (id, name, city_id, status, age_min, age_max)` — ровно под
  `internal/models/cards.go` и под `rows.Scan` в `repo.go`; лишних колонок нет, потому что
  сервер их всё равно не читает;
- индексы `cards_city_id_idx`, `cards_status_idx`;
- 6 городов из ТЗ (Тирасполь, Бендеры, Дубоссары, Рыбница, Каменка, Григориополь) и
  8 анкет: id 1–6 `published`, id 7 `on_moderation`, id 8 `rejected` — чтобы `status` фильтр
  в SQL был проверен на реальных данных;
- идемпотентность: `ON CONFLICT DO NOTHING` + `setval` по обеих последовательностях, скрипт
  можно гонять по кругу.

### Метод

## Кегль: чего в ТЗ нет

Проверили по первоисточнику, а не по памяти: в ТЗ **нет** нормы «не мельче 13 px» для текста.
Есть ровно две числовые нормы — зона нажатия 44×44 (§10.6 п.6) и поля форм не меньше 16 px
(§3.5 п.5, §15.6 п.6); вторая выполнена, поля формы измерены. Фактически в вёрстке текст
метаданных карточек и подписей лежит в 8–11 px (на `/` 103 элемента с кеглем < 13 px, минимум
8 px), и это не нарушение ТЗ, а **дизайн-решение**, которое должен подтвердить владелец
проекта: поднимать шкалу или оставлять как есть — на усмотрение, не самодеятельность.

## Агент 1 — дополнение от 2026-11-05 (решение координатора-2 по `/favorites` и честный статус форм)

Решение принято координатором-2: `/favorites` НЕ закрывается через `requireDemo()`. Избранное —
свойство аккаунта, а не демо-витрина, и гейт по режиму отрезал бы реальных пользователей с

локальное избранное на каноническом каталоге.

список живёт в `localStorage` под ключом `talentro_favorites`, на другое устройство не
переезжает и при очистке браузера теряется. Это же текстом сказано прямо на панели гостя.

Формы без сервера приведены к честному статусу (П.10): отзывы (`ReviewsBlock` + страница
