# Витрина на Vercel

Это про публикацию **одной лишь витрины** (`web/`, Next 16). Go-API и PostgreSQL на Vercel
не запускаются: стек из `docker-compose.yml` живёт на VDS (§1–§9 `docs/deploy.md`), а
витрина с Vercel обращается к нему по публичному HTTPS-адресу.

Проверено на машине разработки 2026-11-04: сборка `next build` **без** переменных
окружения проходит (40 маршрутов, все страницы динамические — API на сборке не дёргается),
`npx tsc --noEmit` чистый, `vitest` — 121 тест, `next start` на собранном билде отдаёт
честную заглушку вместо моков (п.3).

| Поле | Значение |

`node_modules`, `.next` и `.env*` в git не попали (`.gitignore`), так что сборка стартует
с чистой установки. Секретов в репозитории нет: из env-файлов закоммичен только
`.env.example`.

## 2. Переменные окружения

Все `NEXT_PUBLIC_*` вшиваются в клиентский бандл **на этапе сборки**: изменили значение —
нужен redeploy, «перезапуск» не поможет.

| Переменная | Обязательна | Что делает |
| --- | --- | --- |
| `NEXT_PUBLIC_API_URL` | да, иначе каталога нет | публичный origin Go-API **без** `/api` на конце. Из него же проксируются `/media/*` (п.5) |
| `NEXT_PUBLIC_SITE_URL` | для продакшена | базовый URL в `metadataBase`, `robots.txt`, `sitemap.xml` |
| `NEXT_PUBLIC_GOOGLE_CLIENT_ID` | нет | без неё кнопка «Войти через Google» не рисуется |
| `NEXT_PUBLIC_AUTH_URL` | нет | только если сервис сессий живёт отдельно от каталога |

## 3. Что увидит посетитель без `NEXT_PUBLIC_API_URL`

Главная отдаёт текст `Каталог недоступен: на сервере не задан адрес бэкенда
(NEXT_PUBLIC_API_URL). Показать примеры можно только тестировщику.`, счётчики — 0,
выдуманных организаций и занятий в HTML нет (проверено grep по собранному билду).
Так и задумано: примеры из `web/src/lib/data.ts` показываются только демо-режиму
тестировщика (§6 ТЗ), а «бэкенда нет» — это ошибка, а не пустой каталог.

То есть голый импорт в Vercel даёт **макет**, а не рабочий каталог. Чтобы витрина была
настоящей, нужен публичный API-origin (п.6).

## 4. Домен в SEO-файлах

`web/src/lib/site-url.ts` берёт адрес по цепочке:

`NEXT_PUBLIC_SITE_URL` → `NEXT_PUBLIC_VERCEL_PROJECT_PRODUCTION_URL` →
`NEXT_PUBLIC_VERCEL_URL` → `VERCEL_URL` → `http://localhost:3000`.

Выдуманного `talentro.example` в коде больше нет — в превью-деплоях подставляется
настоящий Vercel-домен. `/robots.txt` и `/sitemap.xml` Next собирает статически
(в выводе сборки помечены `○`), значит origin в них запекается **на сборке**: для
продакшена `NEXT_PUBLIC_SITE_URL` надо задать до первого деплоя, иначе в индексе
окажется адрес превью.

## 5. Фото карточек

- В базе фото лежат относительными путями `/media/…`.
- Витрина проксирует `/media/:path*` на `NEXT_PUBLIC_API_URL` (`web/next.config.ts`),
  поэтому картинка становится same-origin и `next/image` работает без `remotePatterns`.
- Сам Go-сервис `/media/*` **не раздаёт**: `GET http://127.0.0.1:8080/media/palitra-1.jpg`
  → 404 (проверено на стенде). Файлы отдаёт Caddy из `/srv/media` (`infra/Caddyfile`).

Отсюда правило: `NEXT_PUBLIC_API_URL` обязан указывать на origin, который закрывает и
`/api/v1/*`, и `/media/*` — то есть на Caddy перед VDS-стеком, а не на `api:8080` напрямую.
Иначе каталог есть, а обложек нет.

Файлов в репозитории нет: их кладёт деплоящий в `/srv/media/cards/{id}/` (§8
`docs/deploy.md`). Пока фото не залиты, карточка показывает пустую обложку «Фото нет».
Раньше на битый путь подставлялась картинка из моков (`/images/kids.jpg`) — это была
подмена, её убрали.

## 6. Требования к API-origin

1. **HTTPS.** Страница на https + API по http = mixed content, браузер запрос не отдаст.
2. **Публичная доступность.** VPN-адрес стенда (`26.52.103.163:8080`) из Vercel не виден.
3. **CORS.** `ALLOWED_ORIGINS` Go-API должен включать адрес витрины. Если витрина и API
   на одном домене (Caddy раздаёт и `/`, и `/api/*`) — переменную можно оставить пустой.
4. SSR витрины ходит в тот же публичный адрес, что и браузер (hairpin-запрос, §4.1
   `docs/deploy.md`): origin обязан отвечать и со стороны сервера Vercel.
5. **Вход.** `POST /api/auth/login` и `/api/auth/register` пока 404 — на Vercel тот же P0,
   что и в аудите. Работают `POST /api/auth/tester` (демо-вход, если на сервере задан
   `TESTER_TOKEN`) и `GET /api/auth/me`.

## 7. Проверка после деплоя

```bash
node docs/acceptance/recheck-stand.mjs \
  --web=https://<адрес-vercel> \
  --api=https://<публичный-api-origin>
curl -s https://<адрес-vercel>/robots.txt   # host должен быть настоящим доменом
```

`recheck-stand.mjs` — матрица P0/P1 из аудита; выход `1` значит, что есть FAIL.
Без запущенного API-origin часть проверок уйдёт в SKIP, каталог и организации станут FAIL —
это ожидаемо и ровно про то, что написано в п.3.

## 8. Чего Vercel не закрывает

- Go-API, PostgreSQL, сиды `database/init.sql`, миграции.
- Раздачу `/srv/media` и сами фото.
- Реальный вход по email/паролю и бэкенд модерации — эндпоинтов ещё нет.
