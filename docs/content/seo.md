# SEO-метаданные витрины Talentro

Подготовлено 4 ноября 2026. Всё, что ниже помечено как «проверено», получено одним из трёх способов:
`curl` к API (`http://26.52.103.163:8080/api/v1/...`) или к витрине (`http://26.52.103.163:3000/...`),
или чтение файлов из `D:\CyberSprint\.worktrees\integration\web\`. Ссылки вида
`web/src/app/...:строка` — на каноническую копию витрины, из которой собран стенд.

Счёт символов — по фактическим строкам этого документа, посчитан `len()` в Python (кириллица и «ёлочки»
считаются как один символ, пробелы тоже).

## 0. Три правила, из которых всё следует

1. **Шаблон заголовка уже дописывает бренд.** `web/src/app/layout.tsx:16` задаёт
   `title.template = "%s — Talentro"` (это +11 символов к каждому `title` страницы). Кроме главной:
   Next не применяет шаблон, когда `title` страницы совпадает с `title.default`
   (`layout.tsx:15`). В таблицах ниже явный случай помечен словом «default».
2. **Нельзя обещать то, чего на стенде нет.** Фото нет (см. §3), рейтингов и отзывов на сервере нет,
   расписания в списке карточек нет. Поэтому в `title`/`description` не идут слова
   «фото», «отзывы», «рейтинг», «расписание по дням», «лучший», «№1».
3. **Адрес канонический — не production-домен.** Проверено: `curl http://26.52.103.163:3000/` отдаёт
   `<link rel="canonical" href="http://26.52.103.163:3000"/>` и `og:url` того же вида, а
   `.env.example` предполагает `NEXT_PUBLIC_SITE_URL=https://talentro.example`. До публичного домена
   все canonical/og:url/sitemap считать черновыми: значения ниже относительные (`/map`, `/about` …),
   абсолют соберёт Next из `metadataBase` (`layout.tsx:13`).

## 2. Шаблоны страниц каталога

Источник полей указан для каждого слота. Всё берётся из канона API, ничего не додумывается.

### `/activities/{slug}`

| Поле | Строка подстановки | Источник |
|---|---|---|
| title | `{name}` → итог `{name} — Talentro` | `GET /api/v1/activities/{slug}` → поле `name` |
| description | `{category} · {city}: {description}`, обрезка по границе слова до 155 | те же запрос: `category`, `city`, `description` |
| og:title | `{name}` | `name` |
| og:description | та же, что `description` | — |
| og:image | **не выдавать, пока `/media/*` не начнёт отдавать 200** | `photos[].path` |

Проверка на фактических данных (8 занятий, `GET /api/v1/activities`):
самое длинное `name` — 40 знаков («Детская музыкальная школа «Весёлые ноты»»), итог с шаблоном — **51 ≤ 60**;
самое длинное `description` — 65 знаков, итог по шаблону — **85 ≤ 155**.
Запас есть, отдельная обрезка заголовка не нужна. Вариант `{name} — {city}` не проходит:
40 + 4 + 9 = 53 и +11 = 64 > 60, поэтому город — только в `description`.

Правила подстановки:
- `description` пустой или короче 20 знаков → брать `org_name` + `category` (`{org_name}: {category} в {city}`);
  ни одного такого случая сейчас нет, но правило фиксируется на случай импорта.
- `price = 0` → в `description` уместно «бесплатно» (таких занятий 2 из 8: id 2 и id 6, проверено в API);
  `price = null` → про цену не писать.
- `kind = "service"` → вместо «секция/кружок» писать «услуга» (1 из 8: id 9, «Репетитор по математике»).
- Возрасты: `age.min`/`age.max` есть не у всех (у id 9 оба `null`) — нет значений, нет и слова «лет».

### `/organizations/{slug}`

| Поле | Строка подстановки | Источник |
|---|---|---|
| title | `{organization.name}` → итог `{organization.name} — Talentro` | `GET /api/v1/organizations/{slug}` → `organization.name` |
| description | `{organization.type} · {organization.city} · {N} {plural}. {organization.description}`, где `N` = длина массива `activities`, `plural` = «анкета/анкеты/анкет» по числу | тот же запрос: `organization.type`, `organization.city`, `activities[]`, `organization.description` |
| og:title | `{organization.name}` | `organization.name` |
| og:description | та же, что `description` | — |
| og:image | **не выдавать** | поля `cover` в ответе API нет (`grep -rn "cover" web/src/lib/*.ts` находит его только в моках `web/src/lib/data.ts`) |

Замеры по 8 организациям стенда (GET по каждому слагу): самое длинное имя — 26 знаков → итог **37 ≤ 60**;
самая длинная `description` по шаблону — **105 ≤ 155**. `N` у всех 8 равно 1, склонение обязательно
(сейчас в коде оно есть: `plural(...)` в `web/src/app/organizations/[slug]/page.tsx:28`, helper — `web/src/lib/utils.ts:4`).

## 3. Чего в метатегах быть не может

Ни в `title`, ни в `description`, ни в `og:*`, ни в JSON-LD — до появления реальных данных:

- **Любое слово про фото и «обложку»** («с фото», «фотографии занятий», `og:image` на путь `/media/...`).
  Проверено: все 7 непустых путей вида `/media/cards/{id}/….jpg` отдают **404 и на API, и на витрине**
  (обход по `GET /api/v1/activities` → `photo` → HEAD на `http://26.52.103.163:3000/media/...`), у id 10
  `photo: null`. Файлов на стенде нет — в `web/public` лежат только `brand/`, `icons/`, `images/` (моки).
- **Оценки, звёзды, «рейтинг», «N голосов», «отзывы» и их число.** Эндпоинтов отзывов/рейтингов нет:
  `GET /api/v1/reviews`, `/api/v1/ratings`, `/api/v1/activities/{slug}/reviews` — все 404 (проверено).
  В ответе карточки голоса/отзывы отсутствуют, а маппер витрины прямо ставит `reviews: []`
  (`web/src/lib/api-server.ts:258`). JSON-LD корректно молчит об `aggregateRating`
  (`web/src/app/activities/[slug]/page.tsx:104`).
- **«Лучший», «№1», «первый в Приднестровье», «только у нас», «проверенный», «официальный».**
  Каталог неофициальный (текст в `web/src/components/legal/LegalLayout.tsx:152`), и сравнить себя
  не с чем — в базе 8 занятий.
- **Обещания расписания** («расписание по дням», «когда заниматься»). В списке витрины у 8 из 8 карточек
  стоит строка `Расписание уточняется`
  (`web/src/components/catalog/ActivityCard.tsx:261`); в `GET /api/v1/activities` поля `schedules` нет,
  группы с расписанием приходят только в деталях карточки.
- **«Проверено» без даты и без источника.** Бейдж «Проверено» сейчас опирается не на дату звонка, а на
  `updated_at` импорта (подробно — `legal-check.md`, строка №19), поэтому в meta-описании это слово пока запрещено.
- **Число занятий как преимущество** («8 занятий в каталоге», «лучшие 8 секций»). Каталог наполняется,
  цифра устареет в тот же день, а на стенде `/api/v1/activities` отдаёт `total = 8`.
- **Реальные контакты, которых нет у продукта.** В `Footer.tsx:19-24` прямо сказано: телефона и почты
  конкурса нет, поэтому в метатегах их тоже не появляется. `organization.email` и `organization.site`
  в API-ответах — `null` (проверено на всех 8 организациях).

2. **`og:title` у всех девяти статических страниц = бренд главной (41 символ).** В коде per-page
   `openGraph` нет ни у одной из них (нет в `page.tsx`, `map`, `about`, `privacy`, `rules`, `terms`,

   но карточка в мессенджере не отличается от главной.
3. **Двойной бренд в заголовках.** `title` страницы уже содержит «Talentro», шаблон добавляет ещё один:

   как баг; в §1 оба заголовка переписаны без бренда.
4. **`/login` с голым заголовком «Вход»** (рендер 15 символов с шаблоном) — самая короткая и самая

   пунктом 6.
5. **`og:image` карточек занятий битый.** Для 7 из 8 занятий `openGraph.images` ставит путь из API
   (`web/src/app/activities/[slug]/page.tsx:61`), и в HTML получается
   `http://26.52.103.163:3000/media/cards/1/palitra-oblozhka.jpg`, который отдаёт 404.

   То же попадает в `twitter:image` (`…/[slug]/page.tsx:69`) и в JSON-LD `image`
   (`web/src/app/activities/[slug]/page.tsx:95`). Пока `/media/*` не починен, тег надо выключать —
   иначе превью в мессенджере выходит пустым, а не «с фото» (что обещано в `web/src/app/terms/page.tsx:118`).
6. **Ни одна закрытая страница не просит `noindex` в метах.** `robots: { index: false }` есть только у
   `/offline` (`web/src/app/offline/page.tsx:8`); у `/login`, `/register`, `/account`, `/favorites`,
   `/moderation` тега `robots` нет (в HTML — `robots=None`). Защита сейчас только в
   `web/src/app/robots.ts:17` (`Disallow: /account, /moderation, /favorites, /api/`) и в
   `web/src/app/sitemap.ts:16-24`, где форм входа/регистрации нет. Для робота это одно, для превью в
   мессенджере и для «случайной» ссылки в индексе — другое.
7. **`Host:` в robots.txt с портом.** `web/src/app/robots.ts:22` берёт `new URL(siteUrl).host`, и на
   стенде выходит `Host: 26.52.103.163:3000` (проверено `curl /robots.txt`). Комментарий в
   `robots.ts:20-21` обещает «голый хост без схемы и порта-https»; на IPv4+порт правило не выполняется —
   директиву имеет смысл отдавать пустой, пока нет домена.
8. **В sitemap 7 URL, карточек нет.** `web/src/app/sitemap.ts:16-24`: `/`, `/map`, `/request`, `/about`,
   `/rules`, `/privacy`, `/terms`. Слаг-страницы (8 занятий и 8 организаций, все живые и индексируемые)
   в файл не попадают — это осознано в комментарии `sitemap.ts:13`, но означает, что ядро каталога
   индексируется только по внутренним ссылкам.
9. **`description` `/request` обещает ответ на почту** — «Модератор проверит источник и добавит анкету
   либо ответит вам на почту» (`web/src/app/request/page.tsx:10`). Отправки нет: заявка пишется в

10. **`description` `/login` обещает голоса и отзывы** — «сохранять занятия в избранное, голосовать и
    писать отзывы» (`web/src/app/login/page.tsx:7`). Голоса живут в состоянии вкладки
