## Топ-10 блокеров выпуска

1. **Авторизация фейковая, серверная сессия не доходит до интерфейса.**
   `AppProviders.tsx:110-190` — «вход» принимает любую почту и пароль ≥ 6
   символов, роль выдаётся по подстроке `moder`/`owner` в почте, всё живёт в
   `localStorage`. Регистрация — туда же. Реальные `POST /api/auth/login` и
   `POST /api/auth/register` отвечают 404 (`route.go:40-43` — только
   google/tester/me/logout). При этом серверная сессия работает:
   `POST /api/auth/tester` → 200, `GET /api/auth/me` с этой кукой → 200
   (`authenticated:true, tester:true`), но `/account`, `/favorites`,
   `/moderation` побайтово совпадают с анонимными, а шапка показывает
   «Войти / Регистрация». Сессию читает только `app/page.tsx:13`.
2. **Кабинет модератора — черновик без бэкенда.** Страница сама пишет:
   «у бэкенда нет ни эндпоинтов модерации, ни таблиц модератора, поэтому
   решения живут до перезагрузки страницы и ничего не меняют в каталоге»
   (`ModerationClient`). MVP §1.2 требует модерацию; к релизу её нет.
3. **Страницы организаций сломаны.** `organizations/[slug]/page.tsx:6,55`
   ищет организацию только в моках `data.ts`. Канонических слагов там нет:
   7 из 8 отвечают 404. Единственное совпадение — `studiya-palitra` —
   отдаёт **другую организацию**: мок-название, мок-телефон, два вымышленных
   адреса, рейтинг 128/6/4 и 4 отзыва, которых нет в API.
4. **Наполнение не выпускное.** В каталоге 8 карточек, из них 1 услуга;
   фотографий 0 из 8 (все `/media/cards/**` → 404, работает только серая
   заглушка); в списке у всех «Расписание уточняется», хотя у части занятий
   расписание есть в API; у репетитора нет возраста (`age.min/max: null`).
   ТЗ §11.2 требует фото минимум у 80 % занятий и «каждую пятую запись —
   услугу». Для «готового сайта» этого объёма недостаточно.
5. **Карта пустая при наличии координат.** API отдаёт `lat`/`lng` у всех 8
   занятий (проверено), но `app/map/page.tsx:24-41` в API-ветке не строит
   маркеры и выводит ложное «Бэкенд пока не отдаёт координаты точек».
   Пользователь видит «0 меток» и недостоверное объяснение.
6. **Все чипы категорий на карточках — «Другое».** `lib/utils.ts:58-59`
   ищет подпись по мок-слагам (`risovanie`, `tancy`, …), а API отдаёт
   канонические (`drawing`, `dance`, …). На карточке занятия хлебные крошки
   при этом правильные — расхождение видно на одном экране.
7. **Часть фильтров и сортировок — мёртвые кнопки.** Наднаправление, время
   суток и сортировка «по оценкам» не отправляются в API
   (`api-server.ts:274-306`), хотя интерфейс их показывает. Замеры:
   `?super=creative-arts` → 8, `?time=evening` → 8, `?sort=rating` — тот же
   порядок. `unsupportedFilters` (`api-server.ts:337`) написан, но в UI не
   подключён; комментарий «их скрывает интерфейс» не соответствует стенду.
8. **Демо-режим тестировщика ведёт на 404.** Блок «Выбор редакции» из
   `app/page.tsx:125-143` подмешивает 6 мок-карточек с выдуманными голосами
   (84/5, 128/6, 96/3…) и ценами; все 6 ссылок
   (`/activities/hudozhestvennaya-studiya-palitra`, `…-kiberhod`,
   `…-chempion`, `…-lapki`, `…-graciya`, `…-spa-ritual`) → 404, потому что
   `activity-page.ts:27-37` при включённом API моки не ищет. Счётчик в демо —
   «18 вариантов» против реальных 8.
9. **Выдуманные данные в шапке и подвале.** Бейдж «2» и уведомления
   («Карточка «Палитра» обновлена 18.10.2026», «В «Чемпионе» открывается
   группа 8–12 лет») захардкожены в `Header.tsx:35,125-143` и видны анониму.
   В подвале `+373 777 00 000` и `hello@talentro.md` (`Footer.tsx:18-21`) —
   неподтверждённые заглушки. «О проекте» обещает «рейтинг без голосов —
   звёзд нет нигде», а страница организации показывает 128 голосов.
10. **Формы и заявки не сохраняются на сервере.** Заявка «не нашли занятие»
    (`RequestClient.tsx:17` — `talentro:requests`), отзывы, избранное,
    правки анкет — всё в `localStorage`. «Гостю — одна заявка в сутки» —
    локальная имитация. `/privacy` обещает лимиты «10 попыток входа в минуту,
    3 регистрации в час», которых нет вместе с самими эндпоинтами.

Вывод: кука тестировщика влияет только на выдачу каталога (`readView` в
`app/page.tsx`). Идентичность пользователя, кабинеты и роли интерфейс берёт
из `localStorage`, поэтому demo-режим — это не вход, а подмешивание моков.
Войти модератором/владельцем можно только фейковой формой: почта с `moder`
даёт роль модератора, с `owner` — владельца.

## Сверка с планом дизайнера и ТЗ

- **Категории.** План `web/src/lib/data.ts` использует транслитерированные
  слаги (`tvorchestvo`, `sport`, `risovanie`, `tancy`), канон §7 — английские
  (`creative-arts`, `sport-fitness`, `drawing`, `dance`). Совпадений по
  слагам нет, поэтому подписи категорий на карточках падают в «Другое».
  Названия наднаправлений в сайдбаре совпадают с каноном — сам список верен.
- **Подписи и блоки.** «Выбор редакции / Рекомендуемое», счётчики
  направлений, уведомления и рейтинги — моки плана, подмешанные в витрину.
  На API-витрине их быть не должно либо они должны быть помечены как пример.
- **Карточка в списке (ТЗ §3.2).** Нет расписания раскрытой группы
  (вместо него «Расписание уточняется»), у репетитора нет возраста.
  «Бесплатно» у футбола формально верно для раскрытой группы 7–10 лет
  (`price_from: 0`), но не сообщает о двух платных группах.
- **Карточка занятия (ТЗ §3.3).** Группы, цены, расписание, телефон,
  мини-карта, «данные ориентировочные» — есть. Галерея показывает «1 / 2»,
  но оба файла 404. Мессенджеры/сайт/почта в каноне пусты — блок контактов
  ограничен телефоном.
- **Организация (ТЗ §3.4).** Не реализована на каноне: мок или 404.
- **Данные (ТЗ §11).** Фото 0 %, услуг 12,5 %, рейтинги без голосов,
  вымышленные уведомления и контакты — прямые нарушения правил «лучше пустое
  поле, чем правдоподобная догадка».
- **Пустой результат (ТЗ §3.1.8).** Есть кнопка сброса и «Оставить заявку»,
  нет трёх карточек «рядом по теме».
