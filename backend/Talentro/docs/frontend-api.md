# API для фронтенда Talentro

Документ описывает маршруты, зарегистрированные в текущем коде сервера. Это рабочая документация по реализации, а не подтверждение, что каждый запрос уже проверен на реальной базе данных. Перед интеграцией нужно прогнать примеры на запущенном сервере и БД.

## Подключение

Локальный адрес по умолчанию: `http://localhost:8080`.

Для JSON-запросов отправляйте `Content-Type: application/json`. Защищённые маршруты требуют заголовок:

```http
Authorization: Bearer <token>
```

Токен возвращается при регистрации и входе, действует 24 часа. Если сервер отвечает `401`, нужно войти заново. Если `403` — аккаунту не хватает роли.

Ошибки имеют общий формат:

```json
{
  "error": {
    "code": "invalid_query",
    "message": "описание ошибки"
  }
}
```

Числовые ID в JSON-ответах моделей карточек и справочников сериализуются строками, например `"id": "12"`. В query-параметрах ID передаются обычными цифрами: `?city=12`.

## Проверка сервера

| Метод и путь | Назначение |
|---|---|
| `GET /health` | Сервер отвечает; не проверяет БД. |
| `GET /ready` | Проверяет соединение с БД. При недоступной БД отвечает `503`. |

## Каталог

### `GET /api/v1/activities`

Возвращает страницу карточек в формате `{ "items": [...], "total": 0, "page": 1, "limit": 20 }`.

Параметры фильтрации:

| Параметр | Пример | Описание |
|---|---|---|
| `q` | `q=рисование` | Поиск по тексту. |
| `city` | `city=3` | ID города, не название. Список ID: `GET /api/v1/cities`. Также принимается старый алиас `city_id`. |
| `district` | `district=2,4` | Один или несколько ID районов через запятую; параметр можно повторять. Старый алиас — `district_id`. |
| `category` | `category=8` | ID направления/категории. Алиасы: `category_id`, `direction_id`. |
| `age` | `age=10` | Возраст ребёнка. |
| `price_max` | `price_max=500` | Верхняя граница цены. |
| `free` | `free=true` | Бесплатные карточки. |
| `kind` | `kind=activity` | `activity` для занятий или `service` для услуг. |
| `online` | `online=true` | Фильтр онлайн-формата. |
| `verified` | `verified=true` | Фильтр проверенных контактов. |
| `day` | `day=1` | День недели числом от 1 до 7. |
| `time` | `time=evening` | `morning`, `day`, `evening`; принимаются также `утро`, `день`, `вечер`. |
| `near` | `near=46.85,29.64` | Координаты `широта,долгота`. |
| `radius` | `radius=3000` | Радиус в метрах от 500 до 10000; требует `near`. Если не указан, для `near` используется 3000 м. |
| `sort` | `sort=rating` | `relevance`, `near`, `rating`, `new`, `free`, `updated_week`. Для `near` нужны координаты. |
| `page` | `page=1` | Номер страницы; по умолчанию 1. |
| `limit` | `limit=20` | Размер страницы от 1 до 100; по умолчанию 20. |

Пример: бесплатные секции в Тирасполе для десятилетнего ребёнка. Сначала узнайте ID Тирасполя через `/api/v1/cities`, затем подставьте его:

```text
GET http://localhost:8080/api/v1/activities?city=3&age=10&free=true&kind=activity
```

`3` здесь только пример ID.

Элемент `items` содержит ID, название, описание, город/район/категорию, тип и формат, цену, возраст, контактные данные, расписание, фотографии и рейтинг. Форма полей определяется моделью `Card` в коде.

### `GET /api/v1/activities/{identifier}`

Получить карточку по числовому ID или slug:

```text
GET /api/v1/activities/15
GET /api/v1/activities/robotics-for-kids
```

### `GET /api/v1/recommended?city=3`

Возвращает до 10 рекомендованных карточек в том же формате пагинации. Сначала берутся карточки с рейтингом и минимум тремя голосами; если их нет, сервер возвращает новые за последние 30 дней.

## Справочники и организации

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/cities` | Список городов. |
| `GET /api/v1/districts?city=3` | Районы; `city` необязателен, но для формы выбора обычно передавайте ID города. |
| `GET /api/v1/categories` | Дерево направлений/категорий. |
| `GET /api/v1/organizations/{id}` | Профиль организации с её карточками и мессенджерами. |

## Регистрация и аккаунт

### `POST /api/v1/auth/register`

```json
{
  "email": "user@example.com",
  "password": "password123",
  "name": "Имя",
  "account_type": "user"
}
```

`account_type`: `user`, `section_owner` или `service_owner`; если поле пропущено, создаётся `user`. Пароль должен быть длиной 8–256 символов. Успешный ответ содержит `token` и объект `user`. Ограничение — 3 попытки регистрации в час с одного IP.

### `POST /api/v1/auth/login`

```json
{
  "email": "user@example.com",
  "password": "password123"
}
```

Успешный ответ также содержит `token` и `user`. Ограничение — 10 попыток в минуту с одного IP.

### Защищённые маршруты аккаунта

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/me` | Получить профиль. |
| `PUT /api/v1/me` | Изменить имя и email; нужны оба поля. |

Пример тела `PUT /api/v1/me`:

```json
{
  "email": "new@example.com",
  "name": "Новое имя"
}
```

## Избранное и голоса

| Метод и путь | Авторизация | Результат |
|---|---|---|
| `GET /api/v1/me/favorites?page=1&limit=20` | обязательна | Страница карточек в формате каталога. |
| `POST /api/v1/me/favorites` | обязательна | Добавляет опубликованную карточку. |
| `DELETE /api/v1/me/favorites/{id}` | обязательна | Удаляет карточку; ответ `204` без тела. |
| `POST /api/v1/activities/{id}/vote` | обязательна | Сохраняет или снимает голос. |

Тело добавления в избранное (ID здесь передаётся строкой):

```json
{ "card_id": "15" }
```

Голос:

```json
{ "value": 1 }
```

`value` — `1`, `-1` или `null` для удаления голоса. Ответ содержит `{ "plus": 0, "minus": 0 }` с актуальными счётчиками.

## Профиль организации владельца

Требуется роль `section_owner` или `service_owner`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/me/organization` | Получить профиль; если он не создан, ответ `404`. |
| `PUT /api/v1/me/organization` | Создать или обновить профиль. |

Пример тела:

```json
{
  "name": "Студия",
  "organization_type": "studio",
  "description": "Описание",
  "phone": "+37300000000",
  "email": "studio@example.com",
  "website": "https://example.com",
  "city_id": 3,
  "district_id": 5,
  "messengers": [
    { "channel": "telegram", "contact": "@studio" }
  ]
}
```

Допустимые типы: `school`, `studio`, `art_house`, `sports_school`, `private_master`. Поддерживаемые каналы: `telegram`, `viber`, `whatsapp`, `instagram`; максимум четыре разных канала. Сайт, если задан, должен начинаться с `https://`.

## Модерация карточек

Требуется роль `moderator`.

| Метод и путь | Назначение |
|---|---|
| `GET /api/v1/moderation/activities?status=pending` | Очередь карточек; статусы `pending`, `published`, `rejected`; по умолчанию `pending`. |
| `POST /api/v1/moderation/activities/{id}/approve` | Одобрить карточку. |
| `POST /api/v1/moderation/activities/{id}/reject` | Отклонить карточку. |

Тело отклонения:

```json
{ "comment": "Укажите корректный телефон" }
```

Комментарий обязателен, от 3 до 1000 символов.

## Что пока не предоставлено API

В текущем коде нет маршрутов создания/редактирования карточек владельцем, загрузки аватара и фотографий, групп занятий и точек на карточке, отзывов и комментариев, жалоб и блокировок, журнала пустого поиска. Также пока не реализованы ETag и правила кэширования из ТЗ. Не подключайте интерфейс к этим сценариям как к готовым.

## Текущий статус проверки

Автоматические тесты и сборка проходят. Интеграционные запросы к реальной БД не выполнялись, поэтому перед выпуском фронтенд-интеграции необходимо проверить SQL и ответы на той БД, с которой запускается приложение. Схема из руководства БД не содержит некоторых сущностей, которые требует ТЗ (в частности, отдельных групп и точек).
