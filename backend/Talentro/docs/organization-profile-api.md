# Голоса, профиль организации и смена пароля

Для запросов кабинета и голосования передавайте `Authorization: Bearer <token>`. Все пути ниже относятся к Go API. Для обложки и адресов требуется аккаунт владельца секций или услуг.

## Голоса

`POST /api/v1/activities/{id}/vote` принимает `{"value":1}`, `{"value":-1}` или `{"value":null}`. Последний вариант снимает голос. Успешный ответ — `200 {"plus":1,"minus":0}`. Обновляйте счётчики по ответу. В каталоге и на странице секции используйте `rating.likes`, `rating.dislikes`, `rating.votes_count` и `rating.score`. Сервер считает рейтинг как разность положительных и отрицательных голосов. Существующие голоса учитываются сразу.

## Адреса и филиалы

Передайте `locations` вместе с обычными полями профиля в `PUT /api/v1/me/organization`. Это работает и при первом сохранении организации, ещё до создания анкеты.

```json
{
  "name": "Школа танцев",
  "organization_type": "studio",
  "phone": "+373 777 12345",
  "city_id": 1,
  "locations": [
    {
      "name": "Основной зал",
      "city_id": "1",
      "district_id": null,
      "address": "ул. Мира, 21",
      "latitude": 46.837,
      "longitude": 29.652
    }
  ]
}
```

- У профиля `city_id` и `district_id` передаются числами JSON. Внутри `locations[]` идентификаторы передаются строками, как в форме анкеты. Для адреса обязательны `city_id` и `address`. Координаты либо отправляйте вместе, либо оставляйте обе пустыми. Район должен принадлежать городу.
- Для нового адреса опустите `id`. При повторной отправке точка с тем же городом и адресом переиспользуется. Для редактирования, особенно если меняется адрес, передавайте строковый `id` из ответа. Сервер принимает до 50 точек за запрос. Пропущенные точки не удаляются, в том числе при `locations: []`.
- Успех — `200` с профилем и сохранёнными `locations[]`, у каждой точки есть `id`. При создании анкеты передайте этот `id` в `locations[]`, а для связи с группой используйте `locations[].key` и `groups[].location_key`. Не создавайте адрес повторно. Название точки приходит как `groups[].location.name`.
- Сервер проверяет принадлежность точки организации. При изменении адреса или других публичных данных точки опубликованные активные анкеты с этой точкой возвращаются на модерацию.

## Обложка

Сначала сохраните профиль. Затем отправьте `POST /api/v1/me/organization/cover` с `multipart/form-data`, поле `file`. Поддерживаются JPG, PNG и WebP до 10 МиБ. Создайте `FormData` и дайте браузеру выставить заголовок с границей частей.

Ответ `200` содержит `{"cover_path":"organizations/42/abc.png"}`. То же поле приходит в `GET /api/v1/me/organization` и `GET /api/v1/organizations/{id}`. Для показа используйте `<API_BASE>/media/<cover_path>`. Если профиль ещё не создан, сервер вернёт `404 not_found`. Повторная загрузка заменяет предыдущую обложку.

## Смена пароля

Авторизованный пользователь отправляет `POST /api/v1/me/password`:

```json
{"current_password":"current-example123","new_password":"new-example123"}
```

Новый пароль должен отличаться от текущего и занимать 8–256 байт UTF-8. Успех — `200 {"message":"Пароль изменён"}`. Неверный текущий пароль даст `403 invalid_current_password`, а если пароль уже изменился параллельно — `409 password_changed`. Лимит — пять запросов в минуту на аккаунт. Если пользователь не знает текущий пароль, оставьте доступным восстановление через письмо.

После смены действовавшие ссылки сброса погашаются. Уже выданные токены входа действуют до своего обычного срока.

## Порядок выкладки

1. Примените `database/migrations/010_organization_profile_and_votes.sql` перед запуском нового API. Миграция добавляет поля и индекс. Она применима и до обновления Go.
2. Выложите бэкенд и проверьте маршруты. Затем подключите их во фронтенде. При регистрации организации сохраняйте адреса после первого входа, затем отправляйте обложку отдельным запросом. При ошибке дайте повторить только тот шаг, который не прошёл.

## Удаление филиала

`DELETE /api/v1/me/organization/locations/{id}` — токен владельца в `Authorization: Bearer ...`, тело не нужно. `{id}` — ID места из `organization.locations`, а не ID секции или организации.

- `204` — филиал удалён, тело пустое. После успеха убрать его из формы.
- `400 invalid_id` — некорректный ID.
- `404 not_found` — места нет или оно принадлежит другой организации.
- `409 location_in_use` — есть привязанные возрастные группы. Сначала перенести их в другое место или удалить группы через редактирование секций. Группы и расписания автоматически не удаляются.
- `401/403` — нужен вход владельца с подходящей ролью.

Пропущенные в `PUT /api/v1/me/organization` места по-прежнему сохраняются: удаление выполняется только отдельной командой. Миграция для этого изменения не нужна.

## Свой голос в карточке

Поле верхнего уровня `my_vote` теперь возвращается в каталоге (`GET /api/v1/activities`, также `/api/cards`), подробностях (`GET /api/v1/activities/{identifier}`), рекомендациях (`GET /api/v1/recommended`) и избранном (`GET /api/v1/me/favorites`). Значения: число `1` — лайк, `-1` — дизлайк, `null` — голоса нет или запрос анонимный. Поле присутствует и при `null`.

В публичные GET-запросы тоже нужно передавать `Authorization: Bearer ...`, чтобы получить голос текущего пользователя. Никакой `user_id` в query передавать не нужно. Без токена каталог остаётся доступным; неверный/истёкший переданный токен даст `401`, заблокированный аккаунт — `403`. Персональные ответы нельзя сохранять в общем кэше прокси; нужно передавать токен каждого пользователя в бэкенд и соблюдать `Cache-Control: private, no-store` и `Vary: Authorization`.

Сохранение голоса остаётся прежним: `POST /api/v1/activities/{id}/vote` с `{"value":1}`, `{"value":-1}` или `{"value":null}` для снятия голоса. При обновлении страницы использовать `my_vote` с сервера, а не старое значение из localStorage. Ответ команды голосования сохраняет прежний формат; при необходимости обновить карточку GET-запросом.
