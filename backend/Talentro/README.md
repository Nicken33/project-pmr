# Talentro — backend

Серверная часть каталога детских секций и услуг. Принимает запросы от фронтенда, достаёт данные из PostgreSQL и отдаёт их в формате JSON.

Стек: Go, роутер [chi](https://github.com/go-chi/chi), PostgreSQL 18, драйвер [lib/pq](https://github.com/lib/pq).

## Как это устроено

```
браузер → handler → repository → PostgreSQL
браузер ← JSON    ← модель     ← строки таблиц
```

- **handler** принимает HTTP-запрос, читает параметры из адреса и отдаёт JSON.
- **repository** собирает SQL-запрос и общается с базой.
- **models** — структуры, в которые складываются данные из базы и которые превращаются в JSON.

## Структура проекта

```
backend/Talentro/
├── cmd/
│   └── app/
│       └── main.go            # точка входа: подключение к БД, сборка, запуск сервера
├── internal/
│   ├── delivery/http/
│   │   ├── handlers/          # обработчики запросов
│   │   └── route.go           # маршруты и подключение middleware
│   ├── models/                # структуры данных (Card, CardFilter)
│   └── repository/            # работа с базой, SQL-запросы
├── go.mod
└── go.sum
```

Правило слоёв: handler знает про repository, repository знает про базу и models. Обратных зависимостей нет.

## Быстрый старт

### 1. База данных

Нужен PostgreSQL 18. Проще всего через Docker:

```bash
docker run -d --name pg \
  -e POSTGRES_PASSWORD=<админский_пароль> \
  -p 127.0.0.1:5432:5432 \
  -v pgdata:/var/lib/postgresql \
  postgres:18-alpine
```

Порт привязан к `127.0.0.1`, чтобы база не была доступна из сети.

Дальше разворачиваем базу из пакета `main_db_handoff` (лежит отдельно, в репозиторий не входит):

1. Создать роли: выполнить `roles.sql`, предварительно заменив `CHANGE_ME_*` на пароли.
2. Создать базу: выполнить `create_database.sql`.
3. Восстановить схему: `pg_restore -U postgres -d main_db main_db.backup`.

```bash
docker exec -i pg psql -U postgres < roles.sql
docker exec -i pg psql -U postgres < create_database.sql
docker exec -i pg pg_restore -U postgres -d main_db < main_db.backup
```

Бэкап содержит только схему, таблицы пустые. Описание таблиц, связей и обязательных полей — в `BACKEND_GUIDE.docx` из того же пакета.

Приложение работает под ролью `catalog_app` (чтение и запись данных). Роль `postgres` для приложения не используется.

### 2. Настройки

Строка подключения читается из переменной окружения:

```bash
export DATABASE_URL='postgresql://catalog_app:<пароль>@127.0.0.1:5432/main_db?sslmode=disable'
```

`127.0.0.1` вместо `localhost` — чтобы не упереться в IPv6. `sslmode=disable` допустим только пока база и сервер на одной машине.

Пароли и файл `.env` в git не коммитятся.

### 3. Запуск

```bash
cd backend/Talentro
go run ./cmd/app
```

В логе должно появиться «успешное подключение к базе данных main_db!». Сервер слушает `http://localhost:8080`.

## API

Базовый адрес: `http://localhost:8080/api`.

### `GET /api/cards`

Список опубликованных карточек (занятия и услуги). Параметры необязательные, комбинируются через `&`. Если параметр не указан, фильтр не применяется.

| Параметр | Тип | Описание |
|---|---|---|
| `city` | число | id города |
| `city_name` | строка | название города (регистр не важен) |
| `age` | число | возраст ребёнка; карточки без ограничения по возрасту тоже попадают в выдачу |
| `q` | строка | поиск по названию карточки |

Пример:

```bash
curl 'http://localhost:8080/api/cards?city_name=Тирасполь&age=8'
```

Ответ — массив карточек. Пустой результат — `[]`.

> Список полей карточки и дополнительные фильтры (направление, цена, формат) дополняются по мере разработки. Актуальные поля смотрите в `internal/models/cards.go`.

## Как строится запрос с фильтрами

Запрос собирается во время работы по тому, какие фильтры пришли:

1. Берётся основа: `SELECT ... FROM cards c JOIN cities ci ... WHERE c.status = 'published'`.
2. Для каждого пришедшего фильтра дописывается условие `AND ...` с номером заполнителя (`$1`, `$2`, ...), а значение кладётся в срез `args`.
3. Запрос и значения отправляются базе раздельно: `db.Query(query, args...)`.

Значения от пользователя **никогда** не подставляются в текст SQL напрямую — только через `$N`. Это защита от SQL-инъекций.

## Правила при разработке

- Все `id` в базе — `bigint`, в Go это `int64`. Для JavaScript id отдаются строкой (`json:"id,string"`).
- Необязательные поля в базе (могут быть `NULL`) в структурах — указатели (`*string`, `*float64`).
- Количество и порядок колонок в `SELECT` должны совпадать с `Scan`.
- В публичную выдачу попадают только карточки со статусом `published`.
- Опечаток в именах папок и пакетов быть не должно: имя пакета совпадает с именем папки.

## Безопасность

- Пароли ролей хранятся вне репозитория (`PASSWORDS.txt`, `.env` в `.gitignore`).
- База доступна только с локальной машины (`127.0.0.1`).
- Для рабочего окружения нужны новые пароли и включённое шифрование соединения с базой.
