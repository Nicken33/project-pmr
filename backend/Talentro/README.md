# Talentro API — инструкция для фронтенд-агента

Подключи интерфейс к существующему Go API Talentro. Сначала изучи структуру frontend-проекта: используй имеющийся API-клиент, настройку адреса сервера, авторизацию и UI-компоненты. Не создавай параллельную систему запросов и не придумывай маршруты, которых нет в этом документе.

Этот документ описывает зарегистрированные маршруты backend-кода. Он не гарантирует, что каждый сценарий уже проверен на текущей БД.

## 1. Подключение

Локальный адрес сервера по умолчанию:

```text
http://localhost:8080
```

Используй переменную окружения фронтенда для API base URL. Не зашивай адрес сервера в компоненты.

JSON-запросы:

```http
Content-Type: application/json
```

Защищённые запросы:

```http
Authorization: Bearer <token>
```

Не устанавливай `Content-Type: application/json` для `FormData`: браузер сам добавляет правильный multipart boundary.

Успешный ответ без содержимого — обычно `204 No Content`. У API-ошибок формат:

```json
{
    "error": {
        "code": "invalid_query",
        "message": "описание ошибки"
    }
}
```

Показывай пользователю `error.message`, когда он есть.

### ID

Большинство ID в JSON-ответах сериализуются строками:

```json
{ "id": "12" }
```

Некоторые ID в JSON-теле запросов также должны быть строками из-за Go-тега `,string`. Ниже для каждого тела указаны конкретные типы. Query-параметры ID передаются обычными цифрами: `?city=12`.

JSON-декодер отклоняет неизвестные поля. Отправляй только поля, перечисленные в теле соответствующего запроса.

### Роли и ответы авторизации

- `401` — токен отсутствует, неверен или истёк; предложи пользователю войти снова.
- `403` — недостаточно прав или активна блокировка аккаунта.
- `404` — объект не найден или недоступен этому владельцу.
- Роль `section_owner` или `service_owner` нужна для управления секциями, медиа и профилем организации.
- Роль `moderator` нужна для маршрутов модерации.

Токен действует 24 часа.

## 2. Проверка сервера

| Метод и путь  | Назначение                                                       |
| ------------- | ---------------------------------------------------------------- |
| `GET /health` | Проверяет, что HTTP-сервер отвечает.                             |
| `GET /ready`  | Проверяет подключение к БД; при недоступной БД возвращает `503`. |

## 3. Каталог, поиск и фильтры

### Поиск карточек

```http
GET /api/v1/activities
```

Также зарегистрирован старый alias:

```http
GET /api/cards
```

Ответ:

```json
{
    "items": [],
    "total": 0,
    "page": 1,
    "limit": 20
}
```

По умолчанию выдаются только опубликованные активные карточки.

Поддерживаемые query-параметры:

| Параметр                 | Пример                           | Значение                                                                                  |
| ------------------------ | -------------------------------- | ----------------------------------------------------------------------------------------- |
| `q`                      | `q=рисование`                    | Ищет по названию и описанию карточки, названию организации и направления.                 |
| `city`                   | `city=1`                         | ID города. Не название.                                                                   |
| `district`               | `district=2,4`                   | Один или несколько ID районов через запятую. Параметр можно повторить.                    |
| `category`               | `category=8`                     | ID направления/категории. Поиск учитывает его дочерние направления.                       |
| `age`                    | `age=10`                         | Возраст участника.                                                                        |
| `price_max`              | `price_max=500`                  | Максимальная цена.                                                                        |
| `free`                   | `free=true`                      | `true` — бесплатные группы; `false` — платные.                                            |
| `kind`                   | `kind=activity`                  | `activity` или `service`.                                                                 |
| `online`                 | `online=true`                    | `true` ищет форматы `online` и `both`; `false` — только `offline`.                        |
| `verified`               | `verified=true`                  | Проверены ли контакты за последние 90 дней.                                               |
| `day`                    | `day=1`                          | День недели от 1 до 7.                                                                    |
| `time`                   | `time=evening`                   | `morning`, `day` или `evening`. Принимаются также `утро`, `день`, `вечер`.                |
| `near`                   | `near=46.85,29.64`               | Центр поиска: широта, долгота.                                                            |
| `latitude` + `longitude` | `latitude=46.85&longitude=29.64` | Альтернативная пара координат; оба параметра обязательны вместе.                          |
| `radius`                 | `radius=3000`                    | Радиус в метрах от 500 до 10000. Требует координаты. По умолчанию для координат — 3000 м. |
| `sort`                   | `sort=near`                      | `relevance`, `near`, `rating`, `new`, `free`, `updated_week`.                             |
| `page`                   | `page=1`                         | Номер страницы, от 1; по умолчанию 1.                                                     |
| `limit`                  | `limit=20`                       | Размер страницы от 1 до 100; по умолчанию 20.                                             |

Координаты и расстояние позволяют искать ближайшие места. Отдельного маршрута карты нет: карточки поиска содержат координаты групп в `groups[].location`.

Пример составного запроса:

```text
GET /api/v1/activities?city=1&district=2,4&age=10&free=true&day=1&time=evening&page=1&limit=20
```

Пример поиска рядом с координатой:

```text
GET /api/v1/activities?near=46.85,29.64&radius=3000&sort=near
```

Для браузерного клиента формируй query через `URLSearchParams`, чтобы корректно кодировать текст и запятые.

Все фильтры города, района, возраста, цены, расписания и расстояния относятся к одной и той же группе и её месту. Если все фильтры подходят только к разным группам карточки, карточка не попадёт в результат.

В карточке ответа есть основные поля, рейтинг, расписания, группы, фото и видео. Структура соответствует полям `Card` в backend-модели; ID сериализуются строками.

### Одна карточка

```http
GET /api/v1/activities/{identifier}
```

`identifier` — числовой ID или slug. Публичный маршрут возвращает карточку только если она доступна в публичном каталоге.

### Рекомендации

```http
GET /api/v1/recommended
GET /api/v1/recommended?city=1
```

Возвращает результат в формате каталога. Если задан `city`, это должен быть числовой ID города. Backend сначала ищет карточки с рейтингом и минимум тремя голосами; если таких нет, возвращает новые карточки за последние 30 дней.

## 4. Справочники

| Метод и путь                   | Ответ                           |
| ------------------------------ | ------------------------------- |
| `GET /api/v1/cities`           | Массив городов.                 |
| `GET /api/v1/districts`        | Массив районов.                 |
| `GET /api/v1/districts?city=1` | Районы указанного города.       |
| `GET /api/v1/categories`       | Дерево направлений и категорий. |

Используй возвращённые ID в формах и фильтрах. Не подменяй их названиями.

Категория имеет поля `id`, `name`, `record_type`, `sort_order` и вложенный `children`, если они есть.

## 5. Регистрация, вход и профиль пользователя

### Регистрация

```http
POST /api/v1/auth/register
```

Тело:

```json
{
    "email": "user@example.com",
    "password": "password123",
    "name": "Имя пользователя",
    "account_type": "user"
}
```

Допустимые `account_type`:

- `user`
- `section_owner`
- `service_owner`

Если поле пропустить, будет создан аккаунт `user`. Пароль: от 8 до 256 символов. Успех: объект с `token` и `user`. Ограничение: 3 попытки регистрации в час с одного IP.

### Вход

```http
POST /api/v1/auth/login
```

Тело:

```json
{
    "email": "user@example.com",
    "password": "password123"
}
```

Успешный ответ также содержит `token` и `user`. Ограничение: 10 попыток входа в минуту с одного IP.

### Просмотр и изменение профиля

Требуется токен.

```http
GET /api/v1/me
PUT /api/v1/me
```

`PUT` принимает оба поля:

```json
{
    "email": "new@example.com",
    "name": "Новое имя"
}
```

Сброс пароля и удаление аккаунта в текущем API не реализованы.

## 6. Профиль организации владельца

Требуется роль `section_owner` или `service_owner`.

```http
GET /api/v1/me/organization
PUT /api/v1/me/organization
```

`GET` возвращает `404`, если профиль ещё не создан. `PUT` создаёт или обновляет его.

Пример тела `PUT`:

```json
{
    "name": "Студия",
    "organization_type": "studio",
    "description": "Описание организации",
    "phone": "+37300000000",
    "email": "studio@example.com",
    "website": "https://example.com",
    "city_id": "1",
    "district_id": "2",
    "messengers": [
        {
            "channel": "telegram",
            "contact": "@studio"
        }
    ]
}
```

Допустимые `organization_type`:

- `school`
- `studio`
- `art_house`
- `sports_school`
- `private_master`

Поддерживаемые каналы мессенджеров: `telegram`, `viber`, `whatsapp`, `instagram`; не более четырёх, без повторов. Если указан сайт, он должен начинаться с `https://`.

**Ограничение текущего backend:** `district_id` принимается в теле, но при сохранении профиля сейчас не записывается. Не обещай пользователю, что выбор района организации сохраняется.

## 7. Создание и управление секциями

Для всех этих маршрутов нужен токен и роль владельца.

| Метод и путь                                | Назначение                                                     |
| ------------------------------------------- | -------------------------------------------------------------- |
| `POST /api/v1/me/activities`                | Создать секцию как черновик.                                   |
| `GET /api/v1/me/activities`                 | Получить список своих секций.                                  |
| `GET /api/v1/me/activities/{id}`            | Получить свою секцию, включая `groups`, `photos`, `videos`.    |
| `PUT /api/v1/me/activities/{id}`            | Полностью сохранить данные секции, группы, места и расписания. |
| `POST /api/v1/me/activities/{id}/submit`    | Отправить готовый черновик на модерацию.                       |
| `POST /api/v1/me/activities/{id}/unpublish` | Снять опубликованную секцию с публикации.                      |

Список владельца сейчас ограничен первыми 100 секциями и не имеет пагинации.

### Тело создания и обновления

Упрощённый пример структуры:

```json
{
    "name": "Секция бокса",
    "description": "Тренировки для детей",
    "direction_id": "3",
    "class_type": "group",
    "class_format": "offline",
    "phone": "+37300000000",
    "locations": [
        {
            "key": "main-hall",
            "name": "Основной зал",
            "city_id": "1",
            "district_id": "2",
            "address": "ул. Примерная, 10",
            "latitude": 46.85,
            "longitude": 29.64,
            "phone": "+37300000000",
            "source_type": "person",
            "source_url": null
        }
    ],
    "groups": [
        {
            "name": "Дети 8–12 лет",
            "age_from": 8,
            "age_to": 12,
            "price_from": 0,
            "price_to": null,
            "price_period": null,
            "location_key": "main-hall",
            "seats": 12,
            "schedules": [
                {
                    "weekday": 1,
                    "start_time": "16:00",
                    "end_time": "17:00",
                    "note": null,
                    "seats": 12
                }
            ]
        }
    ]
}
```

Требования к запросу:

- `name` обязателен, до 200 символов.
- `direction_id` — положительный ID направления, передаётся строкой.
- `class_type`: `individual`, `group` или `both`.
- `class_format`: `online`, `offline` или `both`.
- `direction_id`, `city_id`, `district_id` и существующий `locations[].id` в JSON передаются строками.
- `location.key` связывает место с группой через `group.location_key`.
- Если используется существующее место организации, передай его `id` строкой; менять можно только место своей организации.
- `record_type` не нужно задавать: backend принудительно записывает `activity`.
- Для создания секции у владельца уже должен быть профиль организации.

Успешное создание возвращает:

```json
{
    "id": "42",
    "slug": "sektsiya-boksa-42",
    "status": "draft"
}
```

`PUT` использует ту же структуру. Backend пересоздаёт группы и их расписания из переданного тела, поэтому отправляй актуальный полный список, а не только изменённое поле. При изменении опубликованная секция возвращается на модерацию; отклонённая становится черновиком.

### Отправка на модерацию

```http
POST /api/v1/me/activities/{id}/submit
Authorization: Bearer <token>
```

Тело не требуется. Секция должна содержать необходимые группы, возраст, места, адрес с координатами и расписание.

- Успех возвращает секцию со статусом `pending`.
- `422` — секция ещё не готова.
- `409` — статус не позволяет отправить её на модерацию.

### Снятие с публикации

```http
POST /api/v1/me/activities/{id}/unpublish
Authorization: Bearer <token>
```

Тело не требуется. Доступно для опубликованной активной секции. Успех возвращает секцию; она перестаёт показываться в публичном каталоге.

## 8. Фотографии и видео

Файлы физически хранятся в каталоге `MEDIA_DIR`. API возвращает относительный путь, например `activities/7/abc.jpg`; сам файл открывается по URL:

```text
{API_BASE_URL}/media/activities/7/abc.jpg
```

### Фото

```http
POST /api/v1/upload
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

Поля `FormData`:

- `activity_id` — ID секции строкой;
- `file` — изображение;
- `caption`, `source_url`, `license` — необязательные строки.

Лимит — 10 МБ. Принимаются JPG, PNG, WebP. Ответ `201` содержит `id`, `path`, `alt_text`, `position`, `is_cover`.

### Видео

```http
POST /api/v1/me/activities/{id}/videos
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

Поле формы:

- `file` — MP4.

Лимит — 50 МБ. Ответ `201` содержит `id`, `path`, `position`.

**Важно:** в актуальном коде проверяется MP4-сигнатура, но `ffprobe` ещё не подключён. Проверку длительности до 30 секунд и кодеков H.264/AAC пока не считай работающей.

### Получение списка и показ

Списки `photos` и `videos` включаются в ответ карточки, а для владельца — в:

```http
GET /api/v1/me/activities/{id}
```

Фото показывай через `<img>`, видео через `<video controls>`. URL строится добавлением `/media/` перед относительным `path`.

### Удаление медиа

```http
DELETE /api/v1/me/activities/{id}/media/{mediaID}
Authorization: Bearer <token>
```

При успехе `204 No Content`. Для `mediaID` используй `photo.id` или `video.id`. После ответа убери элемент локально или перечитай секцию.

Backend проверяет владельца и связь с секцией. Опубликованная секция после изменения медиа возвращается на модерацию.

**Ограничение:** текущий маршрут удаления работает с записями `media`, привязанными напрямую через `activity_id`. Для медиа, привязанного только через `location_id`, удаление этим маршрутом не гарантировано. Физический файл удаляется после записи в БД; при ошибке очистки backend пишет сообщение в лог, но всё равно отвечает `204`.

## 9. Избранное и голоса

Все маршруты требуют токен.

| Метод и путь                               | Назначение                                             |
| ------------------------------------------ | ------------------------------------------------------ |
| `GET /api/v1/me/favorites?page=1&limit=20` | Страница карточек из избранного в формате каталога.    |
| `POST /api/v1/me/favorites`                | Добавить карточку в избранное.                         |
| `DELETE /api/v1/me/favorites/{id}`         | Удалить карточку из избранного; ответ `204`.           |
| `POST /api/v1/activities/{id}/vote`        | Поставить или убрать голос за опубликованную карточку. |

Тело добавления в избранное:

```json
{
    "card_id": "15"
}
```

Тело голоса:

```json
{ "value": 1 }
```

Допустимо `1`, `-1` или `null` для удаления своего голоса. Ответ:

```json
{
    "plus": 3,
    "minus": 1
}
```

## 10. Публичные организации

```http
GET /api/v1/organizations/{id}
```

ID организации — положительное число в URL. Ответ содержит профиль организации, мессенджеры и опубликованные карточки организации.

## 11. Модерация

Требуется токен пользователя с ролью `moderator`.

| Метод и путь                                      | Назначение          |
| ------------------------------------------------- | ------------------- |
| `GET /api/v1/moderation/activities`               | Очередь модерации.  |
| `POST /api/v1/moderation/activities/{id}/approve` | Одобрить карточку.  |
| `POST /api/v1/moderation/activities/{id}/reject`  | Отклонить карточку. |

Для очереди можно передать `status=pending`, `status=published` или `status=rejected`. По умолчанию — `pending`.

Тело отклонения:

```json
{ "comment": "Укажите корректный телефон" }
```

Комментарий обязателен, длина от 3 до 1000 символов. Одобрение не требует тела.

## 12. Чего в текущем API нет

Не подключай интерфейс к этим сценариям как к уже готовым:

- создание и просмотр отзывов;
- рейтинг/оценка отзывов, комментарии и ответы организаций;
- жалобы на отзывы;
- загрузка видео к отзыву;
- восстановление пароля;
- удаление аккаунта;
- отдельный маршрут выдачи точек для карты;
- отдельное управление порядком медиа и выбором обложки;
- административное создание и снятие пользовательских блокировок.

Для карты можно использовать координаты групп из поиска; отдельного map API в текущих маршрутах нет.

## 13. Проверка frontend-интеграции

Перед завершением проверь на запущенном backend и подключённой БД:

1. загрузку городов, районов и категорий;
2. поиск с текстом, ID фильтрами, пагинацией и `near`/`radius`;
3. регистрацию, вход, обновление токена в состоянии приложения и `GET /api/v1/me`;
4. создание секции, просмотр списка своих секций, открытие и обновление;
5. отправку готовой секции на модерацию и снятие опубликованной секции;
6. загрузку и показ фото/видео, удаление по ID;
7. избранное, голоса и ответы при ошибках авторизации;
8. отображение пустых состояний, загрузки и ошибок API.

Проверка наличия маршрута в исходниках не заменяет запросы к реальной БД: некоторые SQL-сценарии и ограничения схемы могут отличаться.
